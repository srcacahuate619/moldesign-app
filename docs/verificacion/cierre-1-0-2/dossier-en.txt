15. Provenance and verification instructions
The reproducible package accompanying this dossier includes a `manifest.json` with the role, size, and SHA-256 of each file,
and a sorted `checksums.sha256` file that detects missing, modified, or added files.
Unsealed provenance fields in this run: configuracion_sha256, vocabulario_especies.
How to verify the package without running anything: (1) open the ZIP and read `manifest.json`, which declares each file's
role, size, and SHA-256, including missing files and their reason; (2) recalculate each file's SHA-256 and compare it with
`checksums.sha256`; (3) check that no file is missing or extra relative to the manifest. The ZIP itself, `checksums.sha256`, and
the `manifest.json` entry inside `files` are excluded by design—a file cannot contain its own hash—and the package README
explains this.
A correct checksum demonstrates INTEGRITY: the bytes have not changed since the package was created. It does not show that the method
is suitable, the preparation was correct, or the conclusion is true. Integrity is not scientific validity, and this dossier does not present them as the
same.
These hashes let a third party verify that this dossier's conclusions were calculated from the inputs it declares. An on-chain record certifies
WHEN the document was issued; it does not certify WHAT it was calculated from. Both are necessary; neither replaces the other.
