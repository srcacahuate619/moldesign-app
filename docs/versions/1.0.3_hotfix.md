# HOT FIX 1.0.3 — render de vídeo de Molcy en la versión 1.0.2 de Microsoft Store

**HOT FIX.** Corrige sobre la versión 1.0.2.0 publicada en Microsoft Store un fallo que impedía generar
vídeos con Molcy. No cambia ninguna ruta de cálculo científico. Registro de cambios completo:
[`1.0.3_cambios.md`](1.0.3_cambios.md).

## Síntoma

- Se instala 1.0.2 desde la Store, se crea un caso, se lanza un vídeo con Molcy.
- El trabajo termina con «El render falló · Molcy terminó con código 1; revisa render.log».
- Se generan todos los fotogramas, pero no llega a existir el MP4.
- En el registro del trabajo aparece:

```
File ".../molecularnodes/session.py", line 270, in _pickle
PermissionError: [WinError 5] Acceso denegado:
  'C:\\Program Files\\WindowsApps\\amezcua-dev.com.MolDesign_1.0.2.0_x64__he54t0vnbfj1r\\resources\\backend'
```

## Causa

Blender hereda la carpeta de trabajo del proceso que lo lanza. En el paquete instalado, el backend vive
dentro de `WindowsApps`. Molecular Nodes entra en la carpeta del `.blend` al guardar (`save_post`) y, al
salir, intenta volver a la carpeta heredada. Windows le niega esa vuelta, y el render termina con código 1
aunque el motor haya producido todos los fotogramas.

Medido: un Blender lanzado desde `WindowsApps\...\resources\backend` reproduce el `PermissionError`; el
mismo script lanzado desde la carpeta del repositorio no falla. La medición es aislada, sin la aplicación.

## Arreglo

- Todo proceso del motor declara su carpeta de trabajo (`cwd`). El render de vídeo corre en la carpeta del
  trabajo; las fotos, igual; las sondas de Blender y la instalación del addon, en la carpeta de datos de
  Molcy. `run_owned` ya no tiene valor por defecto: un lanzamiento sin `cwd` no compila.
- Una guardia (`backend/tests/test_molcy_cwd_de_procesos.py`) recorre todos los lanzamientos de
  `services/molcy` y falla si alguno no declara `cwd`.
- Ningún cambio en `tools/molcy`: el motor sigue vendorizado tal cual.

## Segundo problema: el sellado y el halo (encontrado al probar 1.0.3)

Con el primer arreglo, el render de Blender ya termina en la app instalada, pero el trabajo queda
**fallido** (`SELLO_FALLO`) aunque el MP4 existe. Causa: el paso de sellado y el de contraste llaman al Python
del paquete (`resources\python\python.exe`, en `WindowsApps`) desde PowerShell, y Windows responde
`Acceso denegado`. El script no detecta el fallo de arranque, así que el vídeo sale **sin sello**
(no hay `.sha256`) y el halo de los títulos **no se aplica**.

Arreglo (`backend/services/molcy/python_auxiliar.py`): la primera vez, el backend copia a la carpeta de datos
de Molcy lo mínimo de ese Python para que corran los dos scripts: el ejecutable, sus DLL, la biblioteca
estándar y Pillow (unos 35 MiB, frente a 1,4 GiB del runtime). Ese intérprete se pasa al script como
`-Python`. Las fotos usan la misma copia, porque su lanzador también corre como hijo directo del backend.

Verificado fuera de la app instalada: la copia arranca, importa Pillow y ejecuta `sellar_mp4.py` sobre una
copia del MP4 real (`SELLO_MP4`, código 0); `contraste.py` genera el halo sobre un fotograma sintético;
la copia ignora un `PYTHONPATH` ajeno (el que exporta el backend). **Falta la prueba en la app instalada:**
que el trabajo termine en «completo» con `SELLO_OK` en el registro.

## Qué no está medido todavía

- **Un render completo desde el MSIX 1.0.3 instalado.** Las pruebas unitarias comprueban la carpeta que
  recibe cada proceso, no el `PermissionError` de Windows dentro de `WindowsApps`. Eso lo cierra la prueba
  de la aplicación instalada que se describe abajo.
- Si el fallo afecta a otras versiones de Blender o de Molecular Nodes: sólo está medido con Blender 5.2.2
  en una sola máquina (GPU NVIDIA GTX 1660 SUPER).

## Cómo actualizar

La forma normal es la Store: cuando el envío 1.0.3.0 esté publicado, la Store ofrece la actualización a
quien tenga 1.0.2. **Hasta entonces, 1.0.3 no está en la Store y no se puede instalar desde ella.**

Para probarla antes, con el instalador firmado con el certificado de desarrollo (el mismo que usó la VM):

1. **Guarda tus datos.** Copia la carpeta de datos de MolDesign (casos, renders) y, si no quieres
   reinstalar Blender y Molecular Nodes, también la carpeta de Molcy. Desinstalar la aplicación puede
   borrar sus datos locales.
2. Desinstala MolDesign 1.0.2 desde «Configuración → Aplicaciones».
3. Confía en el certificado de desarrollo del paquete en este equipo. **Es una decisión tuya**: sólo
   hazlo en un equipo que controles, y no lo añadas a ningún otro.
4. Instala el `.msix` firmado de 1.0.3.0 (el que dice `x64.msix`, no `store-unsigned`).

El `.msix` sin firmar (`...store-unsigned.msix`) es el que se sube a Partner Center. No se instala a mano.

## Cómo verificar que está arreglado

1. «Acerca de» debe decir **1.0.3**.
2. Abre Molcy, elige un caso con la estructura lista y un formato horizontal 16:9.
3. Genera el vídeo. Debe terminar con un MP4 y el cierre de MolDesign; el estado debe ser «completo».
4. En la carpeta del trabajo, `render.log` no debe contener `Traceback` ni `PermissionError`.
5. Repite con una foto de la escena. Las fotos usan el mismo lanzamiento y no se han medido en la Store.
