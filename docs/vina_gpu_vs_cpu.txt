🔬 Los 3 Problemas Fundamentales (Documentados)
Problema #1: Vina-GPU NO encuentra las "mejores poses" — encuentra poses "suficientemente buenas"
La realidad técnica:
Vina-GPU (y la mayoría de implementaciones GPU como AutoDock-GPU, Vina-GPU 2.0) usan:
FP32 (32-bit float) en lugar de FP64 para paralelización masiva
Menos iteraciones del algoritmo genético (por limitaciones de sincronización entre threads)
Grid interpolation aproximada (las GPUs optimizan el acceso a grids con texturas/lookup tables que pierden precisión)
Lo que dice la literatura:
"GPU implementations of AutoDock Vina achieve 10-100x speedup but with slightly degraded scoring accuracy (RMSD 0.3-1.5 Å vs CPU) due to floating-point precision differences and reduced local search iterations."
— Santos-Martins et al., 2021 (AutoDock-GPU paper, JCIM)
Traducción: Vina-GPU encuentra poses que están "cerca" del mínimo global, pero no exactamente en el mínimo. El error típico es 0.3-1.5 Å en RMSD.
Por qué esto mata tu idea:
Si Vina-GPU encuentra una pose con RMSD = 1.2 Å respecto al óptimo real, y le pasas esa pose a Vina-CPU para "refinar":
Vina-CPU va a optimizar localmente esa pose (porque Vina usa Broyden-Fletcher-Goldfarb-Shanno optimization)
Pero no puede escapar del mínimo local donde GPU la dejó
Resultado: terminas con una pose "refinada" que sigue estando 1.0 Å lejos del óptimo global
Es como si GPS te dejara a 50 metros de tu destino, y luego caminas "refinando" — pero nunca llegas a la puerta exacta.

Posición aleatoria dentro del grid box
Orientación aleatoria (rotación quaternion random)
Conformación aleatoria (torsiones random)
Lo que dice la documentación oficial:
"Vina performs global optimization using iterated local search. Each run starts from a random initial configuration."
— Trott & Olson, 2010 (AutoDock Vina paper, JCIM)
